# Kuá

[English](README.md) | Русский

Kuá (казахское «куә», «свидетель») разбирает записи камер видеонаблюдения у кассы банка. Вы загружаете запись, а
сервис сообщает, нашёл ли он признаки возможных нарушений правил обращения с наличными, и для каждого отмеченного
момента показывает таймкод, от одного до трёх кадров-доказательств, краткое описание того, что видно, и норму, к
которой момент может относиться: акт, пункт, дословную цитату и ссылку на текст на adilet.zan.kz.

Сервис никого не обвиняет. Результат — подсказка для проверяющего, а не юридическое или дисциплинарное заключение.
Всё работает на одном GPU-сервере на открытых моделях; при обработке видео не вызывается ни один облачный ИИ-сервис.

**Основные результаты.** Измерено на 40 размеченных обучающих роликах (единственные размеченные данные, один ракурс
камеры; настройки подбирались на этих же роликах), подробности в [разделе 6](#6-результаты-на-обучающих-роликах):

- Найдено 20 из 21 ролика с нарушением: у каждого размеченного момента есть событие в пределах 2 с.
- Таймкод отличается от разметки не более чем на 2 с у 95,5% размеченных моментов, медиана ошибки 1,0 с.
- В среднем 28,3 с на ролик при обработке по одному.
- Пять длинных роликов, отправленных одновременно, обработаны за 148,9 с при лимите 240 с, без единого отказа судьи на
  запасной вариант.
- К каждой отметке прилагаются 1–3 кадра-доказательства, таймкод и цитируемая норма. Цитаты берутся дословно из текста
  акта на adilet.zan.kz, ни одна модель цитату не пишет (запасной тип `other` ссылается на акт в целом).
- Всё работает полностью локально на одном GPU-сервере.

## 2. Быстрый старт

### 2.1 В браузере

Интерфейс на русском языке.

1. Откройте веб-интерфейс и пройдите страницу-уведомление ngrok.
2. Вставьте API-ключ в поле «API-ключ». Он хранится только в этом браузере.
3. Перетащите видео на страницу или выберите файл (`.mov` или `.mp4`, до 200 МБ) и нажмите «Проверить видео».
4. Страница показывает этап (в очереди, чтение видео, проверка фрагментов, формирование результата) и прошедшее время.
   Она сообщает «до 4 минут»; собственный лимит сервиса — 240 с. В адрес добавляется `#job=<id>`, поэтому после
   перезагрузки страницы или по той же ссылке задача откроется снова.
5. Результат показывает один из двух вердиктов из ТЗ: «Нарушение не обнаружено» или «Обнаружены признаки возможных
   нарушений», а под ним — пометку, что это подсказка для проверяющего. Ниже идут видео со шкалой событий и по одной
   карточке на событие:
   - таймкод (кнопка, которая перематывает видео к этому моменту), тип и фрагмент, который охватывает событие;
   - «Что видно»: что увидела видеомодель, по-русски;
   - «Почему это может быть нарушением»: обоснование языковой модели или осторожный текст из каталога;
   - «Правило и источник»: документ, пункт, дословная цитата и ссылка на adilet.zan.kz;
   - кадры-доказательства (по щелчку открываются крупно);
   - метка: «оценка модели» (тип и формулировку дала языковая модель), «слабый сигнал» (языковая модель не уверена в
     нарушении, поэтому показан осторожный текст каталога) или «по каталогу» (языковая модель не ответила, поэтому тип и
     текст взяты из каталога правил).

### 2.2 Через API

Два шага, как в ТЗ: загрузка и опрос.

```bash
BASE=https://frida-parallelepipedous-cubicly.ngrok-free.dev
KEY=<API_KEY>                      # передаётся жюри отдельно

# 1. Загрузка (multipart-поле "file"). Ответ приходит сразу.
curl -X POST "$BASE/api/v1/analyze" -H "X-API-Key: $KEY" -F "file=@video_017.mov"
# {"job_id":"3f2a9c1e7b4d","status":"processing"}

# 2. Опрос. status: processing, done или failed.
curl -H "X-API-Key: $KEY" "$BASE/api/v1/jobs/3f2a9c1e7b4d"

# Или ждать в цикле и сохранить результат:
JOB=3f2a9c1e7b4d
until curl -s -H "X-API-Key: $KEY" "$BASE/api/v1/jobs/$JOB" -o result.json \
      && ! grep -q '"status":"processing"' result.json; do sleep 3; done
```

Готовая задача возвращает схему из ТЗ (раздел 10) и дополнительные поля. Значения ниже — для иллюстрации;
`image_base64` сокращён.

```json
{
  "job_id": "3f2a9c1e7b4d",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Оставление наличных без присмотра",
      "timecode_sec": 44.2,
      "description": "<что видно> <почему это может быть нарушением> Основание: <документ>, п. 20, ч. 2.",
      "evidence_frames": [{ "timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..." }],

      "type_id": "cash_unattended",
      "rule": { "document": "<название акта>", "clause": "п. 20, ч. 2", "quote": "<дословная цитата>",
                "url": "https://adilet.zan.kz/rus/docs/V1900019680#z112" },
      "confidence": 0.31,
      "observation": "<что увидела видеомодель>",
      "justification": "<почему это может быть нарушением>",
      "type_source": "judge",
      "t_start": 40.0,
      "t_end": 48.0,
      "weak_signal": false
    }
  ],
  "video_url": "/api/v1/jobs/3f2a9c1e7b4d/video?token=<токен задачи>"
}
```

| Поле | Значение |
|---|---|
| `verdict` | `violation`, если сохранено хотя бы одно событие, иначе `no_violation`. Третьего значения нет. |
| `violations` | Сохранённые события по возрастанию времени; `[]`, если вердикт `no_violation`. |
| `type` | Название правила (по-русски), см. [раздел 5](#5-типы-нарушений). |
| `timecode_sec` | Время события в секундах от начала, с округлением до 0,1 с. Это время первого кадра-доказательства. |
| `description` | `observation` + `justification` + `Основание: <документ>, <пункт>.`, так что ссылка на норму есть и в поле, которое определено в ТЗ. |
| `evidence_frames` | 1–3 кадра JPEG (качество 90) в base64: в момент таймкода, в начале и в конце фрагмента; кадр ближе 0,5 с к другому отбрасывается. |
| **Дополнительные поля** | |
| `type_id` | Постоянный идентификатор правила (`cash_unattended`, ..., `other`). |
| `rule` | `document`, `clause`, `quote`, `url` цитируемой нормы. У цитаты уровня документа (правило `other`) `clause` пустое. |
| `confidence` | Вероятность ответа YES видеомодели для фрагмента (0–1, два знака); 0, если проверка не дала ответа. Не откалибрована; событие сохраняется начиная с 0,05. |
| `observation` | Что увидела видеомодель, по-русски. |
| `justification` | Показанное обоснование: от языковой модели либо осторожный текст каталога для слабого сигнала или запасного варианта. |
| `type_source` | `judge` (тип выбрала языковая модель) или `fallback` (она не ответила; тип взят от видеомодели или `other`). |
| `t_start`, `t_end` | Фрагмент, который охватывает событие (ячейка 4 с), в секундах. |
| `weak_signal` | `true`, если собственная вероятность нарушения у языковой модели ниже 0,5: событие сохраняется и показывается с осторожным текстом каталога. |
| `video_url` | Добавляется в каждое состояние `GET /api/v1/jobs/{job_id}`. Загруженное видео; токен в адресе действует только для этой задачи. |

Прочее про `GET /api/v1/jobs/{job_id}`:

- Пока статус `processing`, также возвращаются `stage` (`queued`, `decoding`, `verifying`, `writing`) и `elapsed_sec`.
- При `failed` возвращается `error` (например, если файл не читается как видео).
- `?debug=true` добавляет объект `debug` со всеми фрагментами-кандидатами, сохранёнными и отклонёнными, их оценками,
  временем шагов и версиями использованных моделей и порогов (без изображений).
- `GET /api/v1/jobs/{job_id}/video` возвращает загруженный файл (запросы диапазонов работают). Принимает токен задачи из
  `video_url` или заголовок `X-API-Key`.

| Код HTTP | Когда |
|---|---|
| 401 | Нет `X-API-Key` или он неверный. Проверяется до чтения тела загрузки. |
| 413 | Загрузка больше 200 МБ (переменная сервера `MAX_UPLOAD_BYTES`). |
| 400 / 422 | Запрос не `multipart/form-data` или в нём нет поля `file`. |
| 404 | Неизвестный или неверно составленный `job_id` (идентификаторы — 12 шестнадцатеричных символов). |

## 3. Архитектура, подход и модели

```
 браузер / curl
      |  HTTPS, публичный адрес (туннель ngrok)
      v
 API + UI  :8000   FastAPI. Проверка ключа, очередь (2 рабочих потока), задачи на диске,
      |            лимит 240 с на видео, считая с конца загрузки
      v  для каждой задачи
 1 чтение   декодирование; при необходимости внутренняя копия в нормальной ориентации
 2 нарезка  ячейки по 4 с; проверяется до 16 (равномерно), у каждой по 2 с контекста с обеих сторон
 3 проверка InternVideo3-8B, 4 реплики (:30000, :30002-:30004):
            для фрагмента YES/NO, идентификатор правила, описание по-русски
 4 отбор    P(YES) >= 0.05 или нет ответа; склейка соседей одного типа; вердикт
 5 кадры    1-3 кадра JPEG на каждое сохранённое событие
 6 сопоставление  RAG-сервер :30001: bge-m3 + BM25 + глоссарий, слияние по рангам (RRF)
            Судья Qwen3.5-9B :30005 (SGLang): правило, пункт, P(нарушение), обоснование
 7 запись   цитата копируется из текста акта; JSON-результат
```

### 3.1 Процессы

| Процесс | Порт | Среда Python | Роль |
|---|---|---|---|
| API и интерфейс | 8000 | `env/main` | `api.py`, `pipeline/`, `static/`. Папки задач на диске; незавершённые задачи после перезапуска ставятся в очередь снова. |
| Видеопроверка, 4 реплики | 30000, 30002, 30003, 30004 | `env/iv3` | `servers/iv3_server.py`, InternVideo3-8B-Instruct. |
| Сопоставление с нормами (RAG) | 30001 | `env/main` | `servers/rag_server.py`. Поиск по пунктам и фронт для судьи. |
| Языковая модель-судья | 30005 | `env/vlm` | Qwen3.5-9B на SGLang 0.5.19. |
| Публичный адрес | - | агент ngrok | `tunnel.sh`, пробрасывает публичный адрес на порт 8000. |

Используются три среды Python 3.12, потому что моделям нужны разные версии библиотек (`env/main`: transformers 5.14.1;
`env/iv3`: transformers 4.57.3; `env/vlm`: SGLang). На сервере одна NVIDIA H200 (144 ГБ); при последней проверке наши
процессы занимали около 113 ГБ. GPU-сервер используется совместно с другими задачами.

### 3.2 Модели

| Модель | Для чего |
|---|---|
| InternVideo3-8B-Instruct | Смотрит на каждый фрагмент (4 кадра/с) и отвечает на один вопрос, в котором перечислены все правила: `ANSWER: YES/NO`, `TYPE: <идентификатор правила или none>`, `OBSERVATION: <1–3 предложения по-русски>`. P(YES) берётся из распределения самой модели на первом токене ответа. |
| Qwen3.5-9B | Судья. Получает описание видеомодели, правила-кандидаты и предложенные пункты и возвращает правило, пункт, собственную вероятность нарушения и обоснование в 1–3 предложения по-русски, сформулированное как возможность. Режим рассуждений выключен, температура 0. **Читает только текст, кадры ему не передаются.** |
| BAAI/bge-m3 | Плотные эмбеддинги 247 пунктов и описания события. |
| BM25 и небольшой глоссарий | Лексическая часть поиска (стемминг для русского языка; глоссарий сопоставляет бытовые слова вроде «смартфон» с лексикой актов). Объединяется с плотной частью слиянием по рангам (RRF, k = 60). |

VideoJev-4B (модель поиска событий) и детектор людей RT-DETR (приближение на людях) также есть в `setup.sh` и в коде,
но в развёрнутой конфигурации они выключены.

Модели используются в готовом виде; ничего не дообучалось.

### 3.3 Что происходит с видео

1. **Приём.** Ключ проверяется до чтения тела запроса. Загрузка записывается на диск потоком (лимит 200 МБ) и ставится
   в очередь. Одновременно выполняются две задачи, остальные ждут, и это ожидание входит в лимит 240 с.
2. **Чтение.** Видео проверяется. Если оно не H.264, имеет метку поворота или начинается не с нулевого времени, оно один
   раз копируется во внутренний файл в нормальной ориентации (на сервере нет кодека H.264, поэтому копия в MPEG-4).
3. **Нарезка.** Видео делится на ячейки по 4 с. Проверяется до 16 ячеек: для ролика не длиннее 64 с — каждая ячейка,
   для более длинного — 16 равномерно распределённых. Каждая ячейка проверяется на фрагменте, который начинается на 2 с
   раньше неё и заканчивается на 2 с позже (не более 8 с).
4. **Проверка.** InternVideo3 получает фрагмент и вопрос, в котором перечислены 14 обнаруживаемых правил (13 конкретных
   и запасное `other`; вопрос по каждому правилу берётся из каталога), с указаниями опираться только на видимое, никого не
   опознавать и не описывать и называть людей только «кассир», «клиент» или «инкассатор».
5. **Отбор.** Фрагмент сохраняется, если P(YES) >= 0,05. Фрагмент, по которому проверка не дала ответа (поздний или
   неудачный вызов либо не осталось времени), тоже сохраняется: пропуск хуже ложного срабатывания. Сохранённые события
   одного типа с таймкодами в пределах 3 с склеиваются; при ячейках по 4 с это затрагивает только короткую последнюю
   ячейку, поэтому соседние ячейки остаются отдельными событиями. Вердикт `violation`, если сохранено хотя бы одно
   событие.
6. **Доказательства.** Для каждого сохранённого события вырезаются 1–3 кадра JPEG.
7. **Сопоставление** (для каждого сохранённого события, параллельно; см.
   [раздел 4](#4-нормативные-источники-и-сопоставление-правил-с-видео)). Правила-кандидаты — это `TYPE` видеомодели, до
   четырёх правил, чьи пункты из каталога входят в 8 лучших найденных по описанию, и `other`. Судья выбирает одного
   кандидата и пункт. Если его ответ отсутствует, опоздал или не является допустимым кандидатом, событие получает тип
   видеомодели (или `other`) и текст из каталога.
8. **Запись.** Цитата копируется из текста акта (ни одна модель её не пишет), результат сохраняется вместе с задачей,
   статус становится `done`.

У каждого вызова сервера моделей есть тайм-аут, и он никогда не завершается исключением: неудачный или запоздавший вызов
переводит работу на более дешёвый путь, а не обрывает задачу. Задача получает статус `failed`, если видео не читается
или при непредвиденной ошибке.

### 3.4 Развёрнутые настройки (`thresholds.json`)

| Ключ | Значение | Смысл |
|---|---|---|
| `generator` | `grid` | Нарезать ролик на ячейки и проверять их; модели поиска нет. |
| `cell_sec` | 4.0 | Длина ячейки в секундах. Таймкод события — центр ячейки. |
| `top_k` | 16 | Проверяется не более 16 ячеек на ролик. |
| `verify` | 0.05 | Сохранять фрагмент, если P(YES) не меньше этого значения. |
| `merge_sec` | 3 | Склеивать события одного типа, у которых таймкоды ближе этого значения. |
| `judge_weak` | 0.5 | Если вероятность нарушения от судьи ниже этого значения, событие — слабый сигнал. |
| `verify_mode` | `single` | Один вопрос со всеми правилами (а не по вопросу на каждое правило). |
| `zoom` | `false` | Приближения на людях нет. |

В файле остались также ключи `cand`, `rank`, `strong`, `fallback` и `anchor`, которые генератор `grid` не использует.

### 3.5 Локальная работа

- Сервис обращается только к серверам на `127.0.0.1` (серверы моделей и модуль сопоставления). В окружении заданы
  `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`; веса скачиваются один раз скриптом `setup.sh`. После этого для обработки
  видео интернет не нужен. Туннель ngrok — только путь снаружи.
- Звук не используется, лица не распознаются и людей не опознают.
- В репозитории есть также `tools/rag_eval.py` — измерительный скрипт для разработки с необязательным облачным
  LLM-бэкендом. Он использовался для одного измерения на ноутбуке разработчика. Сервис его не импортирует и не вызывает,
  а сам бэкенд отказывается запускаться на сервере.

## 4. Нормативные источники и сопоставление правил с видео

### 4.1 Источники

Все цитаты в `rules.yaml` дословно взяты из русского текста актов на adilet.zan.kz, прочитанного 2026-10-17 через
публичный API adilet. У каждой цитаты пункта есть ссылка с якорем абзаца.

| Акт | Для чего используется | Прочитанная редакция |
|---|---|---|
| Постановление Правления Национального Банка Республики Казахстан (НБРК) от 29 ноября 2019 года № 231, [V1900019680](https://adilet.zan.kz/rus/docs/V1900019680): правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей в банках второго уровня | Основа 13 из 14 обнаруживаемых правил и всех правил, которые нельзя проверить | Редакция от 12.07.2026 |
| Постановление Правления НБРК от 24 февраля 2020 года № 14, [V2000020075](https://adilet.zan.kz/rus/docs/V2000020075): правила организации охраны и устройства помещений банков второго уровня | `unauthorized_person_in_cash_area` (п. 8, ч. 1) и на уровне документа `other` | Редакция от 24.12.2024 |

В корпусе для поиска (`rag/acts/`) четыре акта и 247 действующих пунктов: два перечисленных выше, НБРК № 49 (обменные
операции с наличной иностранной валютой; главы 1, 5 и 6, [V1900018545](https://adilet.zan.kz/rus/docs/V1900018545)) и
НБРК № 230 (платёжность банкнот и монет, [V1700016120](https://adilet.zan.kz/rus/docs/V1700016120)). Судье может быть
предложен пункт из любого из них; каталог цитирует только № 231 и № 14. Утратившие силу и приостановленные пункты в
корпус не входят. Поправка к № 14 (постановление № 88) приостанавливает до 01.01.2027 её новую редакцию п. 11, 13
(подп. 3), 14 и 16; корпус помечает п. 11, 14 и 16 как приостановленные и исключает их, а каталог не цитирует ни один из
них.

Проверены и намеренно не цитируются: НБРК № 58 от 03.03.2001 и № 394 от 15.11.1999 (утратили силу, заменены № 231),
№ 247 от 24.12.2014 (утратил силу, относится только к подразделениям самого Национального Банка) и № 120 от 28.09.2020
(тоже относится к самому Национальному Банку). Тесты проверяют, что каждый цитируемый пункт есть в корпусе действующих
пунктов и что ни один утративший силу акт не цитируется. Полная таблица источников, правила, ограничения и юридические
оговорки — в [RULES.md](RULES.md) (разделы 1, 3, 4 и 5); сами данные — в [rules.yaml](rules.yaml).

### 4.2 От видео к цитате

1. **Каждое правило записано как нечто видимое.** Запись в `rules.yaml` содержит то, что должно быть видно
   (`visual_criteria`), то, что нельзя утверждать никогда (`never_claim`: суммы наличных, проводки, подлинность банкнот,
   личность человека и т. д.), вопрос YES/NO для видеомодели, осторожный русский текст («может указывать на ...»), а также
   от одной до трёх цитат с дословным фрагментом. Описания действий и ролей никогда не используют положение на экране (это
   проверяет тест), поэтому правила не привязаны к тому, где стоит камера.
2. **Видеомодель смотрит на фрагмент и описывает его.** Это описание — единственное, что связывает картинку с текстом
   закона.
3. **Поиск.** Описание ищется в корпусе: плотный поиск bge-m3 и поиск BM25 (с глоссарием), объединённые слиянием по
   рангам; остаются 8 лучших пунктов. На 15 написанных вручную проверочных запросах правильный пункт попадал в первую
   восьмёрку в 12 случаях при гибридном поиске и в 10 — только при плотном.
4. **Выбирает судья.** Ему показывают описание, правила-кандидаты (критерии, `never_claim`, цитаты) и пункты: сначала
   пункты собственных цитат кандидатов из каталога, затем найденные поиском. Он возвращает идентификатор правила из
   кандидатов, идентификатор пункта из предложенных (или none), свою вероятность нарушения и обоснование.
5. **Цитату копирует код, а не пишет модель.** Для выбранного судьёй пункта документ, «п. N», цитата (найденный
   фрагмент пункта, а если его нет — цитата из каталога) и ссылка берутся из текста акта в корпусе. Если судья не назвал
   пункт или у события нет допустимого ответа судьи, используется первая цитата правила из каталога.
6. **Слабые сигналы.** Когда судья не уверен (его собственная вероятность нарушения ниже 0,5), событие сохраняется с
   правилом и цитатой судьи, но обоснованием становится осторожный текст правила из каталога, а событие помечается как
   слабый сигнал. Судья никогда не меняет, какие события сохраняются, и не меняет вердикт.

Из-за шага 5 отметка может ошибаться в том, что произошло, но не может сослаться на несуществующий пункт.

## 7. Область применения и ограничения

**Область применения**

- **Результат — подсказка** для проверяющего, а не юридическое или дисциплинарное заключение. Вердикта два:
  `violation` и `no_violation`.
- **Только видимое.** Сервис не использует звук, не распознаёт лица и не опознаёт людей, не читает суммы и документы.
- **Девять правил перечислены, но никогда не оцениваются** (таблица в [разделе 5](#5-типы-нарушений)): им нужны данные,
  которых нет на видео. Всё, что вне этих 14 типов, может быть отмечено только как `other`.
- **Рассчитан на одну камеру сверху и одну кассу.** В запросах названы роли и действия, но никогда не положение на
  экране. Все размеченные ролики сняты с одного ракурса (464×848 пикселей, 11,6–142,5 с).
- **Ролики длиннее 64 с обрабатываются выборочно.** До 64 с проверяется каждая ячейка по 4 с; у более длинного ролика
  проверяется 16 равномерно распределённых ячеек, у каждой по 2 с контекста с обеих сторон. Это ограничение следует из
  бюджета времени.
- **Юридическая трактовка — наша.** Акты прочитаны на adilet.zan.kz 2026-10-17 через его публичный API; более поздние
  изменения не отслеживаются, текст на казахском языке не проверялся. `unauthorized_person_in_cash_area` — вывод по
  аналогии: ни один акт прямо не говорит, что посторонним нельзя заходить к кассе, поэтому правило опирается на № 14,
  п. 8, ч. 1 (кассовый узел изолирован запираемым входом). `recount_without_controller` оценивается по видимому:
  контролирующий работник может быть вне кадра. `personal_items_at_workplace` имеет низкую серьёзность: п. 12, ч. 2
  допускает средства связи без функций фото- и видеофиксации, а видео этого показать не может. Клиент, ушедший без
  пересчёта наличных, не отмечается.

**Эксплуатация**

- **Лимит времени.** На задачу отводится 240 с с конца загрузки (ТЗ допускает 5 минут). Одновременно выполняются две
  задачи, остальные стоят в очереди, и их ожидание входит в лимит.
- **Публичному адресу нужен работающий агент туннеля.** Браузер сначала показывает страницу-уведомление ngrok. После
  жёсткого завершения агента ngrok может около минуты отказывать новому.
- **Воспроизведение.** Страница воспроизводит загруженный файл. Если браузер не может декодировать кодек (например,
  HEVC в Chrome), видео не играет, но кадры и таймкоды остаются.
- **Загруженные видео и результаты остаются в папке задачи на сервере.** Автоматической очистки нет.

## 8. Запуск сервиса

Всё лежит в одном корне на GPU-сервере, `/home/jovyan/model_train_amir/` (ниже `<root>`): `svc/` — этот репозиторий, рядом
`env/` (среды Python), `hf/` (веса моделей), `jobs/`, `logs/` и `secrets/`. Скрипты берут пути из `svc/env.sh`, который
держит все кэши, загрузки и временные файлы внутри `<root>` и запускает модели в офлайн-режиме.

**Разовая настройка**

```bash
cd <root>/svc
bash setup.sh tools toolchain main iv3 vlm weights   # любое подмножество; каждую цель можно безопасно повторять
```

Скрипт собирает три среды (только готовые wheel-пакеты, на сервере ничего не компилируется) и скачивает в `hf/` веса
VideoJev-4B, InternVideo3-8B-Instruct, Qwen3.5-9B, детектора RT-DETR и bge-m3.

Два секрета создаются вручную и не входят в репозиторий:

- API-ключ: одна строка без пробелов в файле `<root>/secrets/dev_api_key` (права 600); `api_server.sh` читает его только в
  окружение сервера;
- конфигурация агента ngrok в `<root>/secrets/ngrok.yml` (права 600), которую использует `tunnel.sh`.

**Запуск, в таком порядке**

```bash
cd <root>/svc
bash tools/judge_llm.sh start    # Qwen3.5-9B на :30005. Нужно 35 ГиБ свободной памяти GPU; загрузка занимает минуты.

# Реплики InternVideo3, по одному процессу на порт: 30000, 30002, 30003, 30004 (около 19 ГБ памяти GPU на каждую).
# Отслеживаемого скрипта запуска нет. После `source <root>/env.sh` запустите каждую в фоне:
#   $MTA_ROOT/env/iv3/bin/python -m uvicorn servers.iv3_server:app --host 127.0.0.1 --port 30000

bash tools/rag_server.sh start   # :30001. Загружает bge-m3 и считает эмбеддинги всех пунктов до открытия порта.
bash tools/api_server.sh start   # :8000. С генератором grid готов примерно через 5 с.
bash tunnel.sh install           # один раз: закреплённая версия агента ngrok
bash tunnel.sh start && bash tunnel.sh wait
```

У каждого из `judge_llm.sh`, `rag_server.sh` и `api_server.sh` есть команды `start`, `stop` и `status`. `status` завершается
с кодом 0, если сервер исправен, 3 — если он работает, но ещё не готов, 1 — если не запущен. `stop` посылает TERM и через
60 с KILL и трогает только тот процесс, который опознал как свой. Остановка API обрывает выполняющиеся задачи; при
следующем запуске они ставятся в очередь заново. У `tunnel.sh` команды `install`, `start`, `wait [СЕК]` (код 3, если
точка входа не появилась вовремя), `stop` и `status`. Цикл перезапускает агент, когда тот завершается.

**Проверка без GPU.** Заглушка возвращает одно фиксированное событие-пустышку (текст помечен `[заглушка]`); этого
достаточно, чтобы попробовать интерфейс и API:

```bash
cd svc && uv sync
API_KEY=<любая строка> PIPELINE=stub uv run uvicorn api:app --port 8000
```

Переменные окружения API: `API_KEY` (обязательна), `PIPELINE` (`stub` или `real` на сервере), `JOBS_DIR`, `RULES_PATH`,
`MAX_UPLOAD_BYTES` (по умолчанию 200 МБ), `JUDGE_URL` и `IV3_URLS` (их задаёт `api_server.sh`).

## 9. Репозиторий

| Путь | Содержимое |
|---|---|
| `api.py`, `jobs.py` | HTTP API, очередь и рабочие потоки, папки задач на диске |
| `pipeline/` | Конвейер проверки: `real.py` (шаги), `logic.py` (правила отбора и склейки), `clients.py` (запросы и вызовы серверов моделей), `frames.py` (доступ к видео), `stub.py` |
| `servers/` | `iv3_server.py` (видеопроверка), `rag_server.py` (сопоставление и фронт судьи) |
| `rag/` | Корпус пунктов (`acts/`), поиск, лексический поиск, глоссарий, сопоставление |
| `rules.yaml`, `rules.py`, [RULES.md](RULES.md) | Каталог правил, его загрузчик и проверка, источники и оговорки |
| `thresholds.json` | Развёрнутые настройки |
| `static/` | Веб-страница |
| `eval/`, `data/labels.csv` | Скрипт оценки и разметка 40 обучающих роликов (самих видео в репозитории нет) |
| `setup.sh`, `env.sh`, `tools/`, `tunnel.sh` | Настройка сервера и скрипты запуска |
| `tests/` | Модульные тесты, все модели подменены. В последнем зафиксированном запуске прошло 520. |

Тесты запускаются так: `cd svc && uv sync && uv run pytest -q`. GPU не нужен; для некоторых нужен `ffmpeg`, без него они
пропускаются.
